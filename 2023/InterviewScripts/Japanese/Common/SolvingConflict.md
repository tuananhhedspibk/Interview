# Solving Conflict

チームメンバーでもリーダーでも人間だから対立とか誤解とかがあるのは普通だと思って、でもメンバーとリーダーも 同じチームに属するから最終的には誰が正しい、誰が勝つではなく 「チームの課題解決」や「チームの目標を達成する」ので自分の頭を下げて、コミュニケーションを取って、 コミュニケーションを通じてお互いの悩みと考えてることを深く理解できて、理解したらあってる課題を分析して どちらの点を優先するか、暫定対応ならこうするかを決めて最適な方法を一緒に見つけます。

直近のプロジェクトは DDD アーキテクチャでやることを決めましたが、コード書き方と folder の構築はまだ決まってなくて リーダーと私は一緒にやり方を相談しました、やっぱり対立点が結構あって私がやりたかったのは標準でレヤー分ける、 イベント発火時の書き方も標準で行きたかったんです、でもそのいきかたは時間もかかって他のメンバーに対しても難しくて やっていたのプロジェクトの期限も厳しくてリーダーのやり方で私のやり方より標準ではなかったけど時間かからないし、他のメンバーに対しても 早く把握できたので、リーダーのやり方で行きました。

だから対立または矛盾を解決するためコミュニケーションが非常に大事だと思ってます。
